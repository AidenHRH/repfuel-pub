# 0.24 — logging step by step: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (owner chose native execution for the
> redesign). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Log a meal in a few taps: the meal is guessed, several items (food, drink, snack) go into one basket, packs
scan one after another, amounts are natural ("4 Maltesers"), every food has a photo, search shows your foods first
and shops' versions apart, and takeaways can be estimated.

**Architecture:** The Log food flow gains a basket kept in a small module store (`features/nutrition/basket.ts`), next
to `loggingDay`. Every way of adding still goes through `logAndAnnounce`, which writes the entry at once and, while the
basket is open, adds it to the basket instead of closing the flow; the basket bar's **Log N items** closes the flow and
announces the lot. New food data (sugar, shop, piece size) lives on `food_product` (migration 019); takeaways and
built-in food photos are data files.

**Tech Stack:** Expo SDK 58, Expo Router, expo-sqlite behind `Db`, expo-image, Jest + jest-expo.

**Spec:** `docs/superpowers/specs/2026-10-24-nutrition-redesign-design.md` (Release 0.24).

## Global Constraints

- "Never block logging on optional questions (shop, photo)." Shop has Skip; a missing photo shows an initial tile.
- "Never treat an unknown value as zero; estimates are marked ≈." Unknown sugar is `null`; takeaways are `user_approximate`.
- Meal for the time: "breakfast before 11:00, lunch 11–15, snack 15–17, dinner 17–22, snack after".
- Main nutrients: calories, protein, carbs, fat. Secondary: fibre and sugar, "shown when known".
- Takeaway tabs, in order: Chinese · Indian · Pizza · Chippy · Kebab · Burger · Italian · Thai; half / regular / large,
  pizza by the slice, sides included, values "from published UK nutrition data, written as estimates".
- Own-brand shops: Ashfield Farm → Aldi, Birchwood → Lidl, plus the builder's list.
- Tokens only in `src/theme/tokens.ts`; `npm run check` passes before every commit; tests keep "Log food" and
  "Log workout" buttons on Summary.

## Review Focus

1. Closing Log food with items in the basket: they are already saved, so ask "Keep 2 items?" (Keep / Remove), never lose
   them silently. Test in Task 5.
2. A past day opened from Summary: the basket and every scan go to that day (`loggingDay`), and Log N items returns to that
   day. Test in Task 5.
3. A piece weight of 0, blank or text: refused with a message, nothing saved. Test in Task 3.
4. Offline while multi-scanning: a failed lookup says so and the scanner stays open; items already added stay. Test in Task 6.
5. Open Food Facts `stores` with odd text ("tesco,Sainsbury's , ASDA"): first known UK shop, normalised name; unknown
   text is ignored, not shown. Test in Task 2.
